# Transactions, history and durable anchors

Historical implementation study. The paragraph-local selections, registered
comment fragments, React input ownership and legacy anchor behavior described
below have been superseded. Use the current [session API](editor-session-api.md),
[reference contract](editor-references.md) and [limitations inventory](editor-limitations.md).
Current relative ranges span blocks and restore after local undo; the deleted
legacy-anchor behavior below is not the public relative-range contract.

The [extension-boundary follow-up](editor-extension-boundary.md) extracts this core from the demo schema.

The editor editor now routes local edits and streamed arrivals through a pure transaction function. The rendering pipeline consumes the resulting document. React owns focus, input capture and viewport state; the editing core owns document changes, selection, revision checks and local undo history.

## Design choice

Three shapes were considered:

| Shape                                               | Benefit                                                                              | Limitation                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Whole-document snapshots                            | Simple restoration                                                                   | Undo can erase streamed or concurrent changes; no position mapping |
| Explicit operations with revision mappings          | Deterministic local changes and testable anchors; fits the existing TypeScript model | Requires a separate rebase implementation for collaboration        |
| A CRDT-owned document with relative item identities | Convergence and references can share the same identity model                         | Commits document ownership and persistence to a CRDT now           |

This milestone uses explicit operations. It does not choose an OT or CRDT protocol. Stable identities and durable-reference behavior are requirements for either future integration, but the implementations are not interchangeable without work.

ProseMirror describes steps, inversion and rebasing in its [transform guide](https://prosemirror.net/docs/guide/). Yjs provides item-relative positions and origin-filtered undo in its [documentation](https://github.com/yjs/yjs). Our current anchors are revision-mapped positions, not Yjs-style item-relative identifiers.

## Current contract

A local command supplies a base revision, ordered steps, a history policy, a timestamp for grouping, and optionally a final selection. Steps currently replace text, split or join paragraphs, update custom-block properties or comment replies, and append a streamed batch. Application returns a new state, affected block IDs, position maps and anchor maps. All steps succeed together or the old state remains intact.

```ts
editor.dispatch({
  baseRevision: editor.state.revision,
  origin: 'local',
  history: 'separate',
  time: performance.now(),
  steps: [
    {
      kind: 'split',
      id: paragraphId,
      at: offset,
      rightId: editor.allocateBlockId(),
      rightKey: crypto.randomUUID(),
    },
  ],
});
```

Commands needing a particular resulting selection supply it explicitly. Selections remain paragraph-local in this milestone. Enter replaces a selected range and splits in one transaction. Backspace at a paragraph's start joins its preceding paragraph; Delete at its end joins the following paragraph. Joins do not cross custom blocks. Grapheme boundaries and atomic inline elements are checked before publication.

Split/join preserves formatting, inline elements and identified comment ranges. Comments can span the split through two fragments sharing an ID. Joining coalesces contiguous matching fragments and retains distinct comments.

Numeric block IDs remain local layout handles. Persisted references use a separate stable block key. Seed fixtures have deterministic keys scoped by document ID; newly split blocks get a UUID generated by the command caller and carried in the operation, so replay does not generate a different identity.

## Undo

History retains conditional before/after patches and selection bookmarks, without layout snapshots. With generic containers, patches retain changed root fragments, including affected ancestor branches; they are not selective collaborative inverses. Typing and deletion group across adjacent selections within 750 ms. Cursor movement, paste, structural commands and composition boundaries close groups. Composition updates may stay grouped beyond the typing timeout. History is limited to 256 groups.

Stream appends use an excluded history origin. Undo applies patches only to their expected blocks, leaving appended blocks intact. A failed precondition rejects restoration rather than replacing newer content silently. History groups copy their mapping arrays; they never mutate the append-only revision journal.

These are **local conditional inverses**, not collaboration-safe selective undo. The core does not accept remote edits. Grouping still retains intermediate per-block versions, so long uninterrupted typing groups and the mapping journal need retention policies before production use.

## Durable references

An anchor is a plain JSON value:

```json
{
  "version": 1,
  "documentId": "document-uuid",
  "revision": 42,
  "blockKey": "block-uuid",
  "offset": 18,
  "bias": 1,
  "deleted": false
}
```

Offsets are UTF-16 offsets within a paragraph. Bias `-1` follows the position before text inserted at the same location; `1` follows the position after it. At a split boundary, bias determines which paragraph receives the reference.

`parseAnchor` validates the stored value. `resolveAnchor` replays revision mappings using stable block keys and returns one of:

- `resolved`, with the anchor mapped to the requested document revision.
- `deleted`, with an explicitly marked mapped boundary. Deleted-target status stays marked, including after undo; restoring attachment to resurrected content is not implemented.
- `unavailable`, for another document, a future revision, invalid offsets or missing mapping history.

To resolve an old reference after a restart, persist the document ID, stable block keys, document revision and a contiguous mapping journal from the reference revision to the current document. Tests serialize and reload those values before resolution. Saving only an offset and current document is insufficient. The demo has no database or persistence adapter yet, and its fixed `editor-demo` document ID is a fixture identifier, not an application identity scheme.

Journal compaction must advance stored references or preserve enough mappings to resolve them. Until a compaction policy exists, the journal is retained without truncation. Pair anchors for ranges; range-deletion and affinity policies still need a first-class range-reference API.

## Collaboration work still required

A base revision check detects staleness; it does not resolve it. Before exposing remote transactions, implement and test:

1. A versioned wire format addressing stable keys, operation/client identities and duplicate suppression. Current forward operations can be replayed against a restored local snapshot, but their numeric handles are not a network addressing scheme.
2. An ordering/acknowledgement protocol, pending local operations and rebase rules if choosing OT. A CRDT integration instead needs a defined mapping between shared identities and local document state.
3. Concurrent insert/delete, formatting, split/join and block-property conflict rules. Position maps alone do not establish convergence.
4. Selective undo that removes the local user's change without erasing later remote edits. Existing conditional history patches would need transformation or replacement.
5. Durable storage of revisions and mappings, checkpointing, garbage collection and an explicit policy for long-lived anchors to deleted content.
6. Independent-client convergence tests under delayed, duplicated and reordered delivery.

The immediate useful follow-up is a two-client, in-memory rebasing experiment before networking. It should exercise anchors and selective undo together with concurrent text and structural edits.

## Bulk range replacement

`replaceRanges` replaces ordered, non-overlapping selection fragments and joins
their remaining text into the first text block. Node fragments remove complete
subtrees. The calling extension supplies `pruneEmpty`, the container IDs allowed
to disappear if the replacement empties them. Core text selections use this
step for sibling ranges; the demo's structural command also handles quotes,
lists and embedded tables through the same operation.

Text extensions still own replacement and joining, including marks, comments
and inline objects. The transaction records the equivalent position and anchor
maps, rebuilds affected branches once, and publishes one conditional history
patch. It validates interior grapheme cuts and joined boundaries; the beginning
and end of a complete string need no segmentation. Invalid ranges or extension
results reject the transaction without changing state, history or the journal.

The original Warbreaker select-all/delete took 41 seconds in Chromium. Planning
reindexed the document for each selected block, and applying thousands of
replace/join steps rebuilt indexes and retained intermediate root patches.
The minimized 500-paragraph nested case visited roughly 3.8 million nodes and
created 1,998 patches. Bulk replacement visits about 2,500 nodes and creates
one patch. This addresses partial replacements as well as whole-document
deletion, including typing and plain-text paste over a selection.

Local development-server measurements for 7,280 Warbreaker blocks:

| Browser  | Delete handler | Through two frames | Undo handler | Undo through two frames |
| -------- | -------------: | -----------------: | -----------: | ----------------------: |
| Chromium |          29 ms |              55 ms |         6 ms |                   48 ms |
| Firefox  |          28 ms |              37 ms |         9 ms |                   58 ms |
| WebKit   |          30 ms |              35 ms |         6 ms |                   40 ms |

These timings measure application event handling and animation-frame callbacks,
not browser compositor presentation timestamps. Raw reports:
[before](../artifacts/editor-delete-before.json) and
[after](../artifacts/editor-delete-after.json). Native desktop Safari was also
checked with Cmd-A, Backspace and Cmd-Z in an isolated Warbreaker tab.

```sh
pnpm run check:editor-bulk-delete
BROWSERS=chromium,firefox,webkit pnpm run benchmark:editor-delete
```

The deterministic regression bounds tree visits and history patches, compares
partial backward replacements and anchor mappings with independent sequential
steps, verifies exact undo/redo with later streamed roots, and rejects invalid
Unicode boundaries atomically. The browser benchmark checks full-book deletion,
exact restoration, redo, and input/frame latency budgets.

## Verification

`pnpm run check:transactions` exercises deterministic replay, atomic failure, stable identities, rich split/join round trips, grouped history, stream exclusions, saved-anchor resolution, insertion affinity, deletion and missing-history behavior. Browser cases cover wide and narrow viewports in Chromium, Firefox and WebKit.

Existing editor, large-document and reflow checks remain separate. No new runtime dependency, worker, WASM call or serialization step was introduced on the layout path. The JSON examples and round trips concern persistence tests, not rendering.
